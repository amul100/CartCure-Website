1. SENT INVOICE AMOUNTS CAN BE EDITED
   ------------------------------------
   ✅ RESOLVED (2026-02-05)

   Fix implemented: Added onEdit protection in Code.gs (onEditHandler function)
   that blocks edits to 'Amount (excl GST)', 'GST', and 'Total' columns when
   invoice status is not 'Draft'. The change is automatically reverted and
   user sees warning dialog explaining why the edit was blocked.

   Original Risk: Once an invoice is sent to a client, anyone with sheet access
   could manually edit the amount in Google Sheets.

   Location: apps-script/Code.gs - onEditHandler() function (line ~4449)


2. NO DUPLICATE INVOICE NUMBER VALIDATION
   ---------------------------------------
   ✅ RESOLVED (2026-02-05)

   Fix implemented: Updated generateInvoiceNumber() to check all existing
   invoice numbers before returning. If a duplicate is found, the suffix
   is incremented until a unique number is generated. Added helper function
   getExistingInvoiceNumbers() that loads all invoice numbers into a Set
   for efficient O(1) lookup.

   Original Risk: Duplicate invoice numbers could occur from manual creation,
   data corruption, or race conditions.

   Location: apps-script/Code.gs - generateInvoiceNumber() function (line ~11752)

3. NO NEGATIVE AMOUNT VALIDATION
   ------------------------------
   ✅ RESOLVED (2026-02-05)

   Fix implemented: Added validateInvoiceAmount() helper function that checks:
   - Amount is a valid number (not NaN/null/undefined)
   - Amount is greater than $0
   - Amount doesn't exceed $1,000,000 sanity limit (catches typos)

   Validation added to both generateInvoiceForJob() and generateInvoiceForJobSilent().
   Invalid amounts now block invoice creation with clear error messages.

   Location: apps-script/Code.gs - validateInvoiceAmount() function (line ~11801)

7. DESTRUCTIVE "CLEAR DATA" OPTION IN SETUP
   -----------------------------------------
   ✅ RESOLVED (2026-02-05)

   Fix implemented: Enhanced showHardResetDialog() with multiple safety measures:

   1. Data count warning: Shows exact number of jobs/invoices/submissions to be deleted
   2. Mandatory backup: Creates a timestamped backup copy in Google Drive before
      proceeding. Reset is blocked if backup fails.
   3. Stronger confirmation: Changed from "RESET" to "DELETE ALL DATA" for
      explicit user acknowledgment
   4. Multiple confirmation stages: 3-step process (warning → backup → confirmation)
   5. Success/failure messages reference the backup availability

   The option was kept (rather than removed) because it's useful for:
   - Starting fresh with a new client
   - Testing/demo purposes
   - Recovery from corrupted data

   Location: apps-script/Code.gs - showHardResetDialog() function (line ~21209)
